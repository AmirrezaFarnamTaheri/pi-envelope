## Architecture decisions

- Reuse **one** live CodeIndex and its static import/uniquely resolved call candidates. Do not duplicate graph scanners, RTK rewriting, memory/context hooks or task schedulers.
- The v0.17 native `envelope_code_graph` tool exposes status, neighbors, shortest paths, incoming-degree hubs, **weak components (not semantic/Louvain communities)**, advisory directory boundary audits, and bounded JSON/Mermaid exports.
- Each edge declares whether it is a parsed static import or a syntactic call candidate. Unresolved dynamic calls are not upgraded to known edges; `complete:false` and `reasons` describe known caps and parser gaps. No source code execution or model calls.
- External Graphify/CodeGraph/SDL/TeaRAGs results must be opt-in adapters with schema, project root, freshness and provenance validation; never trusted as native AST evidence without checking.
- No automatic transcript import, credential reuse, LLM extraction, *automatically enabled* filesystem watcher, HTML embedding, network fetch, Git commit, CI failure or provider billing.
- Historical upstream token-savings multipliers are not measured Envelope outcomes.

## v0.18 evidence boundary

`extensions/envelope/graphify-adapter.mjs` adds an explicit reader for local `graphify-out/graph.json` NetworkX node-link documents. It preserves upstream `EXTRACTED`/`INFERRED`/`AMBIGUOUS` labels while tagging **every edge** as an untrusted external assertion; this never upgrades to native AST proof. A separate optional `graphify-out/envelope-sources.json` self-declared SHA-256 manifest can detect byte changes in named project-local source files and in the graph file, and `needs_update` marks known staleness. Files not in that manifest remain explicitly unattested; manifest possession does not prove origin or completeness. The watcher is off until expressly enabled and only reports invalidation. See [Graphify artifact interoperability](GRAPHIFY_ARTIFACTS.md).

## v0.19 evidence boundary

`envelope_memory` requires an explicit `/envelope memory on` toggle, stores notes in owner-only project-scoped SQLite, imports only specific project-local Markdown or Claude Code JSONL files when requested, and does not auto-capture chats. JSONL extraction omits raw commands and assistant responses. Source hashes indicate byte freshness, not truth. `envelope_code_history` computes limited non-merge Git co-change/churn without inferring causal dependency, ownership, or code quality. `envelope_code_context_card` rechecks indexed source SHA-256 and returns bounded symbols/imports/call candidates without source excerpts unless requested. These parts are independently adapted from the patterns documented above, not full ports of their engines. See `docs/PROJECT_MEMORY.md`, `docs/CODE_HISTORY.md`, and `docs/CONTEXT_CARDS.md`.

## v0.20 evidence boundary

The actual Graphify.NET `JsonExporter` was inspected and used to make the external node-link reader compatible with `.NET` `file_path`, `relationship`, and nested location metadata, with foreign absolute paths redacted. Local `envelope_code_retrieve` adds AST symbol/path rank fusion with original-source hashes, no embeddings or automatic raw-source disclosure. Optional `envelope_code_policy`/`architecture-gate.mjs` evaluates reviewed architectural dependency and fan-in rules; it does not run automatically. Git-history co-change now uses NUL-framed filenames, preserving spaces/newlines/tabs. See `docs/GRAPHIFY_DOTNET.md`, `docs/CODE_RETRIEVAL.md` and `docs/ARCHITECTURE_POLICY.md`.

## v0.21 capability and visualization evidence boundary

`envelope_capabilities` reports local mode state and safely checks names of optional PATH executables without launching them; route sequences are advisory only, not dispatched or enforced. Native graph export adds bounded, XML-escaped static SVG and sanitized Obsidian Markdown with Mermaid; no third-party HTML, server, or vault writes. External Graphify / Graphify.NET artifact reader exposes declared communities as untrusted grouping metadata, not inferred graph structure. See `docs/CAPABILITY_COCKPIT.md` and `docs/GRAPH_VIEW_EXPORT.md`.

## v0.22 CLI and orientation evidence (incremental review change)

The post-v0.21 opt-in `graphify-cli.mjs` adapter closes the *invocation* gap identified in the first 16-source audit without installing another Pi extension, scanner, context owner, model provider or task scheduler. It independently adapts fixed-argv `query`/`path`/`explain`, explicit code-only `extract`/`update`, status/freshness gating, user-pinned executable discovery, no API key forwarding, source-root control, bounded CLI output and cancellation. Optional graph-first orientation is idempotent and uses Envelope's **existing** prompt hook. This is a usable slice of `gaodes/pi-graphify`, `juhas96/graphify-pi`, `m4t0t0/cmd-mod-graphify`, and `QuantumKuba/dsh-graphify-plugin` via a single Envelope-owned native tool. It incorporates `claude-rig`'s capability-gated routing principle without automating its hook router or enforcing skill chains.

**Still missing for full parity:** independent Graphify.NET engine execution and SDK APIs; an MCP endpoint; OpenGraphify GraphQL server; cross-agent hook transports and multi-agent tooling; comprehensive semantic/LLM extraction for docs/media; unrestricted/persistent automatic graph rebuilds across arbitrary file types (the new session-only watcher refreshes supported code only after explicit consent); all-language typed engines, proof-oriented analyses, graph database integrations, semantic embeddings and vector stores, full ownership/history risk, transcript auto-capture and controlled provider-billed token/quality benchmarks. These are not disguised as complete by a passing code-only CLI test. In particular, OpenGraphify is not an AST graph engine and must not be silently vendored as one.

Evidence: `tests/graphify-cli-bridge.test.mjs`, `docs/GRAPHIFY_CLI.md`, and Graphify-Labs CLI reference pinned to `6c8002eca4acad58db6160eabcb466e61fc35afb`. Hosted run [42505896631](https://github.com/AmirrezaFarnamTaheri/pi-envelope/actions/runs/42505896631) exercised real pinned `graphifyy==0.9.100` code-only build/query/path/explain/update on a temporary fixture. The independent code watcher has unit/Pi integration tests; its real native filesystem-watch smoke must be separately verified before making cross-platform reliability claims.

## SDL delta / context-budget adaptation (new stacked review candidate)

The independently authored `extensions/envelope/symbol-delta.mjs` and one `envelope_code_delta` tool reuse the **same CodeIndex** and SHA-256 source verification. An explicitly captured, project-scoped, in-memory baseline tracks TS/JS declaration-body hashes; later `compare` reports added, removed and changed declarations plus conservative static importer hints. Compare output has strict UTF-8 serialized-byte limits, stable-version pagination, no raw source text and no automatically billed model actions. Changed Python/Go declaration bodies and duplicate symbol identities are marked uncertain; imports/comments-only byte changes are reported as unattributed instead of claiming full equivalence. Baselines are revocable and do not persist across sessions, deliberately not a second context or memory owner.

This closes a **small slice** of `GlitterKill/sdl-mcp`'s delta-pack and context budget patterns and supports the local impact/review principles of `colbymchenry/codegraph` and `artk0de/TeaRAGs-MCP`. It does **not** implement SDL's stored multi-generation versions/leases, provenance-rich symbol graphs, ranked beam-search graph slices, SCIP/provider cross-references, high-precision runtime blast radius or formal PR risk scoring. It has no new semantic embeddings, vector DB or multi-client MCP server, and does not validate other languages' per-symbol bodies. Details: `docs/SYMBOL_DELTA.md`, `tests/symbol-delta.test.mjs`. Full hosted CI for this branch must pass before marking this adaptation verified.

## Context-slice interoperability (additional stacked review candidate)

`envelope_code_slice` composes one CodeIndex, `envelope_code_retrieve`, and `envelope_code_context_card` to return task-scoped evidence without a second graph/embedding index. Exact path or lexical task seed selection, static file import traversal to depth 0–3, 150-file expansion cap, and 1–12 item pages preserve conservative link provenance. Each card is hash-verified against indexed source; smaller skeleton/ETag references can replace full cards to meet strict serialized UTF-8 byte budgets. Source and import-edge hashes bind pagination versions, and supplied ETags can omit unchanged card payloads. No raw source text, network activity, provider costs, automatic memory changes, runtime call proof or claimed model token savings. See `docs/CONTEXT_SLICE.md` and `tests/context-slice.test.mjs`.

This is a **partial** assimilation of graph-slice/conditional-card patterns from `GlitterKill/sdl-mcp`, and surgical local retrieval goals from `colbymchenry/codegraph` and `artk0de/TeaRAGs-MCP`. It does not implement SDL's persistent slice handles and leases, beam-search symbol graphs, SCIP/provider facts, vector/semantic retrieval, CodeGraph's Rust multi-language kernel or TeaRAGs trajectory/architecture risk signals. The full 16-source goal is still open in issue #10.

## Bounded cochange-without-direct-import diagnostics (stacked review candidate)

The one `envelope_code_coupling` tool reuses Envelope's bounded non-merge Git co-change history and the current CodeIndex direct file-import graph. It source-hash-verifies each candidate and identifies repeated co-edits where a direct static import was **not detected**, with optional comparison against directly linked pairs. Outputs are bounded to 100 Git commits, the top 20 historical coedit candidates, 1–10 results per page and a 900–16000-byte serialized JSON cap, with version-guarded continuations. No causal/risk/ownership assertion or automatic CI gate is derived from correlations. See `docs/COCHANGE_REVIEW.md` and `tests/cochange-review.test.mjs`. This is a narrow TeaRAGs/ops-codegraph-tool-inspired diagnostic, not their trajectory engines, 34-language semantic graphs, embeddings or full PR-risk frameworks. Full parity remains open in issue #10.
